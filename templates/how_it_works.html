Project Architecture Guide

1. Web Request Lifecycle

Every time you click a navigation link, view a list, or submit a form, a round-trip communications lifecycle occurs between your web browser and the Python Flask backend server.

Here is the step-by-step path of a request:

1
Browser Client Request: You request a page (e.g., visiting /dashboard). The browser initiates a standard HTTP request.
2
Flask Router Matching: Flask receives the request and searches app.py for a decorator containing that path: @app.route('/dashboard').
3
Python Logic execution: Flask executes the associated view function, checking if the session cookies exist, loading lists from the JSON files, and computing stats.
4
Jinja2 Template Compilation: Python executes render_template('dashboard.html', stats=stats). Jinja2 reads the template file, replacing loops and variables with raw data to compile flat HTML.
5
HTTP View Response: Flask returns the compiled HTML string. Your browser renders the interface and runs the custom client scripts.

2. Core Python Standard Modules

To implement this project without heavy third-party framework code, we leverage standard Python built-in utility modules:

  • flask (Flask, render_template, request, session, redirect): The core micro web framework. Handles routing paths, processes server request metrics, manages signed session state cookies, and compiles Jinja2 templates.
  • json: Formats text string data into Python data structures (lists and dicts) and encodes Python lists back into standard file systems representation.
  • os: Performs operating-system independent file path manipulations so that the backend can load data files correctly on Windows, Mac, or Linux systems.
  • uuid: Generates "Universally Unique Identifiers" (128-bit random strings) to assign safe primary keys to goals, notes, and academic marks records.
  • datetime: Statically stamps creation logs and counts day durations for opportunities countdown metrics.

3. Secure Hashed Authentication & Session Cookies

Why We Never Store Plaintext Passwords

Storing user passwords as plain text in a database is a major security risk. If an unauthorized person gets access to data/users.json, they would see everyone's password. To prevent this, we use the cryptographic hashing tools in werkzeug.security:

Password Hashing (generate_password_hash): When a user signs up, the backend hashes their password. Hashing is a one-way mathematical function. It turns the password (like my_password123) into a long, scrambled string (like scrypt:32768:8:1$7f...). You cannot decrypt this back to find the original password.

Hash Verification (check_password_hash): When logging in, the server takes the password entered in the login form, passes it through the exact same hash formula, and compares the resulting scramble with the hashed string stored in users.json. If they match, the user is authenticated.

How Flask Sessions Work

HTTP is a stateless protocol, meaning each webpage request is completely independent. The server doesn't automatically know if you are the same person who logged in a second ago.

To remember who you are, we use a Session. In Flask, session acts like a dictionary where we can save user information (like session['user_id'] = user_id). This data is stored in the user's browser inside a cookie.

To make this secure and prevent users from changing their cookie data to impersonate someone else, Flask signs the session cookie cryptographically using our app.secret_key. If a user tries to modify their cookie values, the signature check fails, and Flask automatically invalidates the session.

4. Local JSON File Database & GPA Mathematics

Rather than setting up complex SQL servers, this project uses local flat JSON files inside the data/ folder. A JSON file represents structured data directly using key-value fields, mapping seamlessly to Python dictionaries and lists.

Below is a sample course grade record from data/marks.json:

{ "id": "e963625f-22a0-4ff6-8367-bf988b489d8d", "course_name": "Introduction to Programming", "semester": 1, "credits": 4, "mtt1": 8.5, "mtt2": 9.0, "ica": 27.5, "term_end": 72.0, "total": 81.0, "grade": "A+", "gp": 9 }

Academic Grade Calculations

The backend automatically handles grades calculation inside app.py using standard college grading rules:

  • Weighted Term End: Term-End exams are evaluated out of 100 on papers but scaled down to a weight of 50%. The weighted exam score = term_end * 0.5.
  • Total Marks: Summed as MTT 1 (max 10) + MTT 2 (max 10) + ICA (max 30) + (Term End * 0.5), yielding a total score out of 100.
  • Grade Point (GP) Allocation:
    • Marks ≥ 90: Grade O (GP: 10)
    • Marks ≥ 80: Grade A+ (GP: 9)
    • Marks ≥ 70: Grade A (GP: 8)
    • Marks ≥ 60: Grade B+ (GP: 7)
    • Marks ≥ 50: Grade B (GP: 6)
    • Marks ≥ 40: Grade C (GP: 5)
    • Marks < 40: Grade F (GP: 0)
  • Semester SGPA: Weighted average of that semester's course grades:
    SGPA = Sum(Course GP * Course Credits) / Sum(Course Credits)
  • Cumulative CGPA: Calculated as the weighted average grade point of every course logged in the system.

5. Processing Form Data Safely

Every time you log a study session or create a reminder note, Flask performs a structured process to save your input data:

  1. Submit Request: The HTML form is configured with method="POST", sending form fields securely inside the request body rather than in the URL query string.
  2. Extract Values: Python catches the form submission and reads the inputs using request.form.get('field_name').
  3. Database Append: The controller opens the correct database file (e.g. notes.json) using load_data(), appends a new dictionary record, and writes the list back to disk using save_data().
  4. Flash & Redirect: To prevent the browser from submitting duplicates on page refreshes, we return a redirect(url_for('notes')). We use Flask's flash() to queue up a success message display on the next page load.

6. Python Language Features Used

Here are two important Python coding patterns used in this project that make our code clean and concise:

1. Python Dictionaries

A dictionary stores data in key-value pairs. Dictionaries are incredibly convenient for database records. For example:

# A note is a Python dictionary new_note = { 'id': 'a82bc...', 'title': 'Algorithms MTT Prep', 'content': 'Study Big-O notation and Sorting proofs', 'color': 'yellow' }
